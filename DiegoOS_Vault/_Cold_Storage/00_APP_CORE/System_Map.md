# System Map

## Stage 1 operating grammar

Core → Deliverable → Project → Action → Closure

Overflow → PARK_HERE

Repeated blockage → Review Ring later

## Object distinction

Deliverable = produced object
Action = movement
Maintenance = life-preserving action without deliverable

## Deliverable types

Input = prepared material
Process = intermediate artifact
Output = usable result

## Stage 1 folders

- 00_APP_CORE: rules that must not drift
- 03_DELIVERABLES: what must exist
- 04_PROJECTS: current containers of work
- 05_ACTIONS: daily and weekly execution
- 06_REVIEW_RING: later review, mostly inactive in Stage 1
- 07_CAPACITY_POOL: overflow and not-now material
- Inbox: raw capture
- _templates: reusable note shells
